# Соглашения

## Код

- TypeScript strict, без `any` (если без него никак — комментарий почему).
- Логика — в чистых функциях `src/lib/…` с тестами; компоненты тонкие.
- Серверные компоненты по умолчанию, `"use client"` — только где нужны состояние или браузерные API.
- Импорты из `src` — через `@/…`.
- Комментарии на русском и только про «почему». Сознательное ограничение: `// shortcut: <ограничение>, <когда переделать>`.
- Не добавлять зависимость ради пары строк. Новая зависимость — упомянуть в PR зачем.
- Цвета — только токены из `src/app/globals.css`.

## Тесты

- Нетривиальная логика (бронь, деньги, генерация мест, парсинг) — с тестом.
- SQL — тестами на PGlite в `tests/db/` с теми же миграциями.
- Перед PR: `npm run typecheck && npm run lint && npm test`; если менялись страницы — `npm run build`.

## Git

- Ветки от `main`: `feat/…`, `fix/…`, `chore/…`, `docs/…`.
- Коммиты — Conventional Commits на английском: `feat: hold seats from cart`, `fix: release expired holds on confirm`.
- В `main` — через PR, второй разработчик смотрит. Изменения брони — ещё и субагент `booking-reviewer`.
- Не коммитить `.env.local`, `.dev.vars`, ключи.

## Работа с ИИ-агентами

- Правила — в `AGENTS.md` (единственный источник), остальные файлы ссылаются на него.
- Агент должен прогнать проверки и честно написать, что не проверил.
- Миграции на удалённый Supabase и деплой агент делает только по явной просьбе.
